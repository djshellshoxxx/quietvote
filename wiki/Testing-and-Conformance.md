## Test layers (target)

| Layer | What it covers | When it runs |
|---|---|---|
| L0 Static | Strict TypeScript, linting rules (for example, no `Math.random`, constant-time comparisons for secrets) | Every change (per spec 11). Typecheck runs in CI. Lint rules other than the claims lint are not yet configured. |
| L1 Unit | Encoders, hashing wrappers, proofs, Merkle tree, tally arithmetic | Every change. Present for all packages. |
| L2 Vectors | Known-answer, negative and mutation vectors | Every pull request (target). Candidate sets exist in `test-vectors/v1`, generated by `packages/protocol/test/vecgen`. |
| L3 Property | Invariants with generated inputs | `packages/protocol/test/property.test.ts` (small set). Nightly larger runs are not set up. |
| L4 Integration | Server, storage, board, trustees, CLI end to end | Partly present (`packages/server/test/e2e.test.ts`, `packages/protocol/test/e2e.test.ts`, `packages/trustee/test/`). |

Adversarial cryptographic tests (spec 11 section 6), fuzzing and mutation testing (section 7), and load and chaos testing (section 8) are specified. They are not part of the repository's test runs.

## Conformance

- **Test vectors:** candidate JSON sets in `test-vectors/v1` (primitives, protocol, elections, mutations, canary). Their README states that no independent implementation has reproduced them yet and that the manifest is unsigned.
- **Verifier conformance:** a canary self-test and mutation vectors check that the verifier rejects bad inputs.
- **Cross-implementation suite:** not built. A second implementation is planned (roadmap phase P4).

Any change to encodings, domain strings or vectors is a protocol change.

## Public claims

- Banned-phrase lint: `node scripts/lint-claims.mjs`. It runs in CI as a non-blocking job named `claims-lint`. Its findings are a to-do list, not a gate.
- Claims register: [docs/claims/claims-register-v0.md](https://github.com/djshellshoxxx/quietvote/blob/main/docs/claims/claims-register-v0.md). Each claim has a status and an evidence pointer.
