# @quietvote/verifier: implementation notes

Status: first cut. Spec sources: QV-05 (V1..V14), QV-08 D5, QV-11 (INV-17, ATK-012/029), QV-34 section 9.4, QV-16 App. C.

## What it is

A deliberately thin composition, no cryptography of its own:

* `verifyBundle(input, opts)` = `loadBundle` (strict QV-JSON, closed member set) + `protocol.verifyElection` +
  (when the bundle carries a `board` member) `board.verifyLog`, folded into one `VerifierReport`:
  `verdict` (PASS / FAIL / INCOMPLETE), `checks` V1..V14 (`pass | fail | not_run`, each with notes), the underlying QV-34 `chk.*`
  statuses, findings, warnings, caveats, counts, results, `reportHash`, optional `selfTest`.
* `formatReport` renders the same data as text. `qv-verify` (`src/bin.ts`) is the stand-alone entry; `qv verify` in
  `@quietvote/cli` is a front-end over the same functions.
* Bundle format = the protocol `ElectionBundle` (`manifest, manifest_hash, roll, log`) plus optional `board` = `board.bundleToJson(LogBundle)`.
  Unknown top-level members are an error. Bytes are parsed with `parseQvJson` (duplicate keys, floats, lone surrogates rejected).
* Offline: no network, no clock, no randomness. The only I/O is reading the bundle and `canary/corpus.json`.
* Exit codes (`qv-verify`, `qv verify`): 0 PASS, 1 FAIL (or self-test failed), 2 usage, 3 INCOMPLETE, 4 unreadable input.

## Canary / self-test

`canary/corpus.json` (generated by `node packages/verifier/scripts/build-corpus.ts`, drift-checked by a test) holds the known-good control
(`tiny-yesno-3v`), the QV-34 canary election and all 15 mutants, plus 11 synthetic hostile inputs derived in `src/canary.ts`
(null, truncated/duplicated JSON, emptied roll/log, flipped manifest hash, dropped/reversed log entries). `runSelfTest`:
the control must PASS; every canary must be rejected (verdict not PASS, or at least one named check failing: see below) and fail
exactly the checks named in its expectation; synthetic inputs must not PASS and must not throw. `qv verify` runs it first by default
(about 5 s) and forces FAIL if it fails (`--skip-selftest` records a caveat). QV-34 says the canary is signed with every build;
the corpus is not signed yet (the vector MANIFEST is unsigned too).

## Decisions and deviations

1. **V mapping.** V1 = manifest hash+sig; V2 = no `E_ROLL` and the pipeline got past the roll; V3 = DKG; V4 = log integrity: board
   append-only + witness (both layers, see item 9) and `chk.receipts.sample` when any receipt was checked; V5 = `chk.ballots.valid`; V6 = latest; V7 = time window; V8 = Benaloh; V9 = aggregate; V10/V11 split `chk.tally.decrypt`
   by finding code (`E_DEC_PROOF`/`E_TALLY_INSUFFICIENT` vs `E_DLOG_RANGE`, both fail if neither); V12 = rules; V14 = no encoding
   failure and a tally record present (else `not_run`). `reportHash` = SHA-256(RFC 8785 of the report without `reportHash`/`selfTest`).
2. **V13 is always `not_run`** (no Appendix C step; control entries of QV-ADR-022 are not parsed). Not a pass, printed as not run.
3. **V4 never passes on absent input** (INV-17): no board export => `not_run`; unwitnessed (quorum 0 / latest checkpoint short of quorum)
   => `not_run` with "NOT WITNESSED"; redacted bodies (`PARTIAL`) => `not_run`. Any board failure => `fail` and verdict FAIL.
4. **Board trust anchors** come from the signature-verified manifest (`bb.log_pk`, `bb.witness_quorum`); witness identities can only come from
   the bundle (self-attested, the board warning is kept). A bundle can make the quorum stricter, never laxer. If the manifest does not verify,
   the board layer is skipped. Author keys accepted = coordinator keys, trustee `sign_pk`, roll keys, plus caller-supplied `extraAuthorKeys`;
   anything else fails closed (`QV_BOARD_AUTHOR_UNRESOLVED`). The board's manifest entry digest (`qv/body/v1`) is a different hash from the
   protocol manifest hash, so the two are not cross-pinned yet (no QV-16-encoded manifest body inside board entries). Board entry bodies are
   not parsed against protocol records (board NOTES 3/5): ordering of ballot entries between the two representations is not compared.
9. **Log layer (C3) is wired in.** When the bundle has a `board` member, `verifyBundle` passes the raw JSON export to
   `protocol.verifyElection(election, {log})` together with the caller's `witnesses` (X-23 fallback, used only when the manifest lists
   none), `observedCheckpoints` plus `pinnedCheckpoint` (log-signed notes are evidence, others ignored with a warning) and `receipts`.
   Protocol results: `chk.board.append_only` (entry/record binding, tree heads, forks, rollback), `chk.board.witness` (gates, X-23),
   `chk.receipts.sample` (G-V2, clash = ALARM, broken promise = F, malformed = I), `chk.time.window` (witnessed times, V7). They are
   combined with the board layer's own statuses by "any fail fails, both pass passes, otherwise not run" (`both` in verify.ts), so
   neither layer can be bypassed. The report carries a `log` section (`LogLayerSummary`: the four protocol statuses, where witness keys
   came from, counts) and the text output prints one `log layer (QV-16 C3)` line. Without a board export the log layer is absent and
   `receipts`/`observedCheckpoints` are reported as not checked (caveat).
10. **Verdict PASS with failed checks.** Protocol NOTES X-10/X-11: ignored ballots (L-class) and Benaloh alarms fail named checks but keep
   the verdict PASS. The text report prints `FLAGGED: ...`; the self-test treats "some named check fails" as rejection (QV-34 section 9.3).
6. **Pinned manifest hash** (`--manifest-hash`) replaces the bundle's own `manifest_hash`, which is attacker-controlled.
7. **Independence (QV-08 D5).** The package imports only `@quietvote/crypto`, `protocol` and `board`. D1 says L3 packages never import each
   other, yet the requested `qv verify` makes `cli` import `verifier`; flagged for the owner. `qv-verify` here is the D1-clean path.
   The production-dependency closure is `@noble/*` via crypto. No second implementation exists (G4 still open).
8. `verifyElection` also returns `jointKey` and `ctx` (hex) now (two optional fields added to `VerificationReport`) so the CLI can build ballots.

## Known gaps

* No worker threads / resumable verification (QV-11 scale row); no HTML offline page (the offline `verifier.html` is built by
  `packages/web` from the protocol API, not from this package); no signed corpus; redaction handling is coarse; no board-level canary
  in the corpus (covered by tests only).
* **Board grammar vs protocol log (open, owner: board).** `board` requires a `roll_commit` before `election_open` even when the
  manifest carries `roll.root`, and a `tally_aggregate` before `tally_result`. The protocol log produces neither (a roll-commit is
  required only when `roll.root` is absent, and the tally is a single `tally` record). Every tallied or roll-root log therefore fails
  the board layer with `QV_BOARD_GRAMMAR` and V4 fails. `test/helpers/sim.ts` emits a roll-commit to satisfy the grammar; the
  tally case is avoided in `test/logcheck.test.ts` (those elections verify as INCOMPLETE).
* **Shipped test vectors do not bind their log (open, owner: test-vectors / protocol).** `test-vectors/v1` manifests carry a constant
  placeholder `bb.log_id` (836ff184...c213) that is not SHA-256 of `logOrigin(manifest)` (X-21), so `E_LOG_BINDING` on any board export
  built for them. Left unchanged (zero-diff). Tests build their own conformant elections instead; new vectors would be the fix.
* Test helpers `test/helpers/{sim,board}.ts` are copies of `packages/protocol/test/helpers` (test-only), with the protocol import
  changed and one addition: a `witnessPolicy` option on `buildBoard` (board.ts). Re-synced after QV-ADR-015 (`election-open` carries
  manifest_hash, joint_key_seq, roll_commit_seq; sim order is dkg-final, roll-commit, election-open; `electionOpenBody` imported from the
  protocol package); the local roll-commit workaround is gone. Re-sync by hand; regenerate `canary/corpus.json` with
  `node packages/verifier/scripts/build-corpus.ts` whenever test-vectors change.
  changed and two additions: a roll-commit before election-open, and a `witnessPolicy` option on `buildBoard`. Re-sync by hand.

## CLI (`packages/cli`, binary `qv`)

* Zero third-party dependencies, hand-written parser (`src/args.ts`: long options only, `--k v` / `--k=v`, `--`, unknown option = usage error).
* Commands: `verify`, `selftest`, `keygen`, `ballot encrypt|audit`, `board verify`, `election inspect`, `vectors check`.
  Exit codes: 0 ok/PASS, 1 failure, 2 usage, 3 INCOMPLETE/PARTIAL (not a pass), 4 unreadable/malformed input, 70 internal.
* **keygen**: voter key = Ed25519 seed (32 bytes), from `--seed-file`, `--seed-stdin` or the system CSPRNG. Neither seed nor passphrase is ever
  taken from argv (QV-30 S12; `--seed` / `--passphrase` are unknown options). **Passphrase protection is on by default** now that `packages/crypto`
  exports `argon2idKdfAsync` (kdf.ts): the file is a QVKEY1 container (Argon2id + AES-256-GCM, default m=64 MiB t=3 p=1, floor 19456 KiB / t=2,
  ceiling 256 MiB / t=10, adjustable with `--kdf-memory-kib` / `--kdf-iterations`), byte-compatible with `packages/web/src/key/keystore.ts` except that
  the passphrase is canonicalised with NFKC only (the web client also folds word-list passphrases to lower case/single spaces; a word-list passphrase
  typed differently may not unlock a key made by the other client). The passphrase comes from `--passphrase-file` (first line), `--passphrase-stdin`
  or a hidden-echo terminal prompt (asked twice on keygen); minimum 12 characters, no entropy estimate. `--no-passphrase` writes the plain
  `qv-voter-key/v1` JSON with a warning. Files are mode 0600 and never overwritten without `--force`. `ballot encrypt` unlocks protected keys the same way.
  The unprotected seed and the protected container are the only places a voter secret is stored; the audit file (mode 0600) holds the ballot randomness.
* **ballot encrypt** runs `protocol.verifyElection` on the election bundle first and refuses to use a joint key whose manifest/DKG did not verify;
  it requires the voter key to be on the roll. Cast or spoil (`--intent`); spoil needs `--audit-out` (mode 0600; holds `xi` and the selections) and
  is `private` by default, `--publish-reveal` is an explicit opt-in with a warning (QV-ADR-020). Unspecified contests are cast blank (noted).
  Randomness is the hedged `buildBallot` with the system CSPRNG (injectable in tests). Output files are never overwritten.
  The Benaloh flow is therefore "encrypt as spoil, audit on a second device with `ballot audit`, then encrypt the real cast"; a spoil and a cast
  are separate encryptions by construction (a spoiled ballot can never be cast, X-10).
* **ballot audit** checks roll membership, signature and proofs (`verifyEnvelope`), recomputes the ballot from `xi` (`verifySpoilReveal`) and
  checks `reveal_digest`; it does not look at the log (whether the spoil was posted is the verifier's V8).
* **board verify** accepts a standalone `qv-bundle/v1` JSON (anchors from flags: `--log-key`, `--manifest-hash`, `--author-key`, `--pin-file`;
  without author keys the result is PARTIAL, exit 3) or an election bundle with a `board` member (anchors from the verified manifest).
  Deterministic tar containers, `.ots` anchors and SHA256SUMS (board NOTES 10) are not read: JSON form only.
* **election inspect** only describes (hash match, contests, counts, record histogram); it prints that it is not a verification.
* **vectors check** verifies MANIFEST.json hashes and coverage, runs every known-answer/negative vector for the operations in its table
  (hash, ristretto, scalar, Ed25519, canonical JSON, roll, manifest, CDS, limit, PoK, DLEQ, partial decryption, ballot verify/encrypt, Benaloh,
  rules), and the elections / mutants / canary through `verifyBundle`. `dkg.adjudicate` needs the generator-side adapter and is reported as
  `SKIP` (`--strict` turns skips into failure). It duplicates the operation table of `protocol/test/vectors.test.ts` on purpose (that file is
  test code); a new operation must be added to both, otherwise it is reported as SKIP (not run).
* D1 deviation: `cli` imports `verifier` (the request asked for `qv verify`). `qv-verify` (`packages/verifier/src/bin.ts`) is the independent path.
* `qv verify` runs the 29-case self-test every time (about 5 s); `--skip-selftest` is recorded as a caveat in the report.
