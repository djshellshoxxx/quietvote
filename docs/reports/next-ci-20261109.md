## Repairs

The pseudo-locale fixture bundles the app and transitive workspace sources, but
its old path filter only selected web source/static files, the fixture itself,
and its own workflow. A lockfile-only change therefore did not exercise this
browser fixture. The filter now covers all packages, root package manifests and
lockfile, root TypeScript configuration, and `.github`. It retains the ordinary
documentation exclusion and adds merge-queue and manual dispatch entry points.
The package glob is deliberately conservative; it avoids maintaining a second
handwritten transitive dependency graph.

The production browser job previously used separate default-success steps, so a
failure in one journey prevented later journeys from running. A small Bash
runner now executes all five journeys (`run`, `help`, `a11y`, `verifier`, and the
integration lead's `spoil-shares` journey), logs an error for every failed suite,
and returns failure if any suite fails. It sets `QV_REQUIRE_BROWSER=1` itself.
Browser installation still must succeed before the runner starts. Job timeout
and cancellation still stop work; incomplete or cancelled runs are not passes.
The new fifth journey must be integrated with this change.

All three CI script test files run in the supply-chain job. The action-pin
scanner is unchanged: it enforces its documented bounded block syntax, not
arbitrary YAML/schema validation. The new path tests inspect the repository's
specific event/path-list layout and exercise its current literal/`*`/`**`
patterns; they are also not general YAML or GitHub glob validators. Unexpected
path-list syntax fails for review instead of being silently accepted.
