# Product model: what the specs define vs what the code does

Snapshot: `the ab84f16 snapshot` (read-only). Spec cites are `docs/NN:line`; code cites are repo-relative. Honest status: unaudited prototype, not for real elections. Row-level evidence is in `product.reqs.jsonl` (180 rows).

## 1. Public vs private elections; who/how is visible; Phase 1 vs Phase 2
- Specs: audit record is "public by default; group may restrict reading to roll members but not the verifiability" (docs/02:219). Optional `log_read_during_open = members` (docs/06:233, QV-06-REQ-011). Observers (public) are a role (docs/02:102).
- Code: only two access modes, `public` and `link` (read key in `QV-Read-Key`, server NOTES "Event stream"; `packages/server/src/app.ts:300`, `:321`). Roll-key-signed member-only log reads (QV-06-REQ-011) do not exist.
- Phase 1 identity = mode B pseudonymous voter key, invite-enrolled (docs/04:33, :40-42). Public in Phase 1: roll keys, which keys cast, when, and how many ballots per key (revotes), ciphertexts and proofs; never the choice (docs/04:46). Labels per `disclosure.roll_labels`. Operator sees TCP-layer IP unless Tor (docs/04:46).
- Code matches the "who voted" part: `GET /elections/:id/voters/:kid` and `.../ballots` are unauthenticated (`app.ts:596`, `:605`); ballot author is a public KeyId in the entry header (D-21 recorded). Roll labels are never published (roll is keys only, `app.ts:582`).
- Phase 2 blind tokens (docs/04:172-205, QV-04-REQ-018/019) and Phase 3 nullifiers (docs/04:207) are marked later (docs/02:198, :200). Code has only `roll.scheme = ed25519-roll-v1`, `weights = uniform` (`packages/protocol/src/schema.ts:217`). No identity_mode field.

## 2. Voting methods
- v1 scope (docs/02:187): yes/no, single-choice, approval, k-of-n. Out of v1: ranked (Schulze / Ranked Pairs), weighted, delegation (Phase 2, docs/02:199); write-ins "Later", need mixnet (docs/02:202). Withdrawal unsupported; revoting or a blank ballot instead (docs/02:217; D-06 default).
- Code: `ManifestContest.method` is exactly those four (`packages/protocol/src/types.ts:30`; validation `manifest.ts:96-117`; winners and exact-integer tie handling `rules.ts:13-47`). Yes/no needs a threshold `rule`; blank ballots allowed (`min_selections: 0`). Ranked, weighted, delegated: not implemented (weights are a literal `uniform`, leaf weight fixed 1, `manifest.ts:21`). Abstain/eligible-basis options not implemented (decision register N-27).
- Python verifier implements the same four (`verifier-py/qv_verifier/rules.py`; `verifier-py/tests/test_protocol.py#test_qv03_reference_table`).

## 3. Eligibility, duplicate-vote rule, withdrawal
- Spec flow: single-use invite (>=128 bit, hashed, default 14 d), client keypair, proof of possession binding group/invite/pk/label, key-backup confirmation (docs/04:239-244, docs/02:99-101). Roll = Merkle root (RFC 9162) over keys sorted by pk, leaf `"QV-leaf/1"||pk||weight` (docs/04:64-66); fixed at manifest signing (docs/04:115, QV-04-REQ-009). Member states INVITED..ROTATED with suspend/revoke/rotate (docs/04:99-110); lost-key recovery by k-steward `roll.amend` with 24 h delay and old-key veto (QV-04-REQ-011).
- Code: invites 16 random bytes stored as SHA-256, single-use, optional expiry (`app.ts:480-545`); registration verifies PoP over `QV-REG-v1\0 election_id \0 pk` only, auto-approves (`app.ts:546-575`). Roll closes at `roll_commit`, which must equal the approved set (`election.ts:998-1012`); leaf is `pk||u32(1)` without the QV-leaf/1 prefix (`manifest.ts:21`). Not implemented: steward approval, suspend/revoke, rotation certificates, roll amendment, vouching, enrollment log entries, default 14-day expiry, enforced key-backup gate (`qv.key.mustBackup` unused, `packages/web/src/i18n/en.ts:138`).
- HELD B3-01: web hashes the invite and signs over the hash; server expects raw code and `(election_id, pk)` (`packages/web/src/flow/onboarding.ts:128` vs `app.ts:571`). Do not resolve here.
- Duplicate-vote rule (docs/04:156-166, QV-02-REQ-043, QV-04-REQ-008): one counted ballot per voter, latest by log order when revoting allowed, first only when single; replay idempotent. Code uses a `supersedes` hash chain instead of numeric sequences (`election.ts:1037-1040`, `ballotlog.ts:159-175`): wrong supersedes -> E_SUPERSEDES; over `max_per_voter` -> 429 REVOTE_LIMIT/E_REVOTE_LIMIT (not E_ALREADY_VOTED); duplicate ballot code by another voter -> E_DUP_CODE; identical bytes replay returns original receipt (`election.ts:590-601`). Server hard cap `max_per_voter <= 20` (`election.ts:911`) though schema allows 1000.
- Ineligible keys: author must equal ballot voter and be in the roll, checked before any proof work (`election.ts:1033`; `packages/server/test/negative.test.ts#bad signatures and non-roll authors never reach the proof verifier`).
- Withdrawal/suspension: no withdrawal (matches spec). No member suspension or post-snapshot exclusion (QV-04-REQ-015, QV-02-REQ-014 not implemented).

## 4. Governance and proposals
- Specs in MVP scope: group `GroupRules` chain with k-steward signatures (docs/03:20-98, QV-03-REQ-001/002), proposals with versions, review period (docs/03:206-215, QV-02-REQ-020..024), election state machine and guards (docs/03:140-190), extension (docs/03:200), quorum/threshold/ties with exact arithmetic (docs/03:222-256), challenges/arbiter sortition (docs/03:257-278), emergency halt with caps (docs/03:279), amendment classes/entrenched fields (docs/03:216-221), templates T1-T3 (docs/03:295). Delegation is Phase 2 (docs/02:199).
- Code that exists: manifest hash-pinned and m-of-k coordinator-signed (`manifest.ts`, `election.ts:894`); lifecycle DRAFT..ARCHIVED plus PAUSED, INVALIDATED, CANCELLED, ABORTED, derived STALLED (`packages/server/src/lifecycle.ts:12-62`); quorum and yes/no thresholds, ties (`rules.ts`); pause/resume/invalidate by coordinator m-of-k with `maxHalts` (`election.ts:933-946`); operator keys cannot act (`logcheck.ts:202`).
- Not in code: GroupRules, rule versions, proposals/amendments/review period (backlog T-066, T-195 open), schedule minimums (E_SCHEDULE), challenges, disputes, arbiters, sortition, entrenched fields, close-time extension, trustee-initiated halt, templates T1-T3 (only four method templates in `packages/web/src/flow/organizer.ts:6`). CHALLENGED exists only as an enum value. Automatic open/close is owner decision D-91; control-entry shape D-87.

## 5. Cryptographic ballot verification model
- Spec (docs/02:132-151, docs/07:548-561): client encrypts and proves; signed receipt with inclusion proof; Benaloh cast-or-audit; any observer verifies manifest, DKG, roll, every ballot, tree consistency, aggregate, decryption proofs, rules, from a bundle offline, per-check PASS/FAIL with report hash; second verifier before Reviewed.
- Code: matches in substance. Ballot proofs and Benaloh (`packages/protocol/src/ballot.ts`, `packages/web/src/flow/ballot-controller.ts:227`); receipts and RFC 9162 tree heads (`packages/board/src/receipt.ts`, `merkle.ts`, checkpoint after every append); voter checks later inclusion and rollback/fork (`packages/web/test/audit2.test.ts` W2); verifier with 14 checks and report hash (`packages/protocol/src/verify.ts:46`, `packages/verifier/src/report.ts:85`); Python second verifier (`verifier-py/`).
- Verifier gaps: V13 (control entries) always `not_run`; pause/invalidate authenticated but never applied (`logcheck.ts:481`); no release-hash check; report does not include roll size or superseded counts. TS-vs-Python report differences HELD (D-92..D-96; `scripts/compare-verifiers.ts` exits 1 by design).
- Trust model: threshold t-of-n Feldman DKG with PoK (QV-07-REQ-012); trustee shares at rest under scrypt N=2^18, mode 0600 (`packages/crypto/src/bundle-cipher.ts:21`); trustees decrypt only their locally recomputed aggregate after close and above the privacy floor (`packages/trustee/src/trustee.ts:647`).

## 6. Offline / decentralized claims and non-claims
- Claimed: offline verification from an export bundle (docs/02:148, docs/07:61); self-hosted single server acting as untrusted coordinator plus board (docs/07:27); witness cosigning hooks and mirrors as MVP "Should" (docs/02:198 table row). Code: `.qvb`/`export.json` with Range support, read-only import as mirror (`packages/server/src/imports.ts`), gossip of signed tree heads with equivocation evidence (`gossip.ts`), manifest witness keys with quorum (`logcheck.ts:504`).
- Not claimed / not built: P2P operation is "Research" (docs/02:204); "decentralized" is not a security property (docs/07:704); no witness tiers, no monitoring poll, no `.qvx` restore, no WAL rollback markers (B2-07 open). Alternate submission under censorship is D-52 (M3).

## 7. Explicit non-claims and privacy limits (as the specs state them)
- No anonymity of participation in Phase 1; ballot-to-key linkable by design (docs/06:195, docs/07:656 N-4, docs/02:225). Shipped UI: nc4 `en.ts:98`.
- No coercion resistance or receipt-freeness; revoting is partial mitigation; spoil openings and receipts can be abused (docs/06:196, docs/07:653 N-1, docs/02:226). Shipped UI: nc3 `en.ts:97`; receipts/exports carry no vote proof except opt-in spoil reveal (QV-07-REQ-072).
- No protection if voter device or served JavaScript is compromised (docs/06:197, docs/07:655 N-3); build-hash check against signed release manifest is not implemented (QV-07-REQ-054).
- Operator trust: operator is trusted for availability only (docs/07:660 N-8); steward set is trusted for roll correctness, nothing proves one person has one key (docs/04:48-50, docs/07:662-663 N-10/N-11). UI does not state the steward-trust fact (QV-04-REQ-014 partial).
- >= t colluding trustees break secrecy (docs/06:198, docs/07:654 N-2); t=1 allowed with a warning only (`manifest.ts:144`).
- Small groups and unanimous results reveal votes (docs/06:163-181, :203). Code: `min_counted_ballots` floor (default 5 if roll>=8 else 3, `manifest.ts:45`), `privacy_ack` needed below 10, W-SMALL-ROLL warning (`manifest.ts:147`); the web UI never renders these warnings (`packages/web/src/flow/election.ts:157` stores them, no consumer) and has no unanimous-result warning (QV-07-REQ-017).
- Network metadata: no network anonymity without Tor (docs/06:200, docs/07:659 N-7). Code: IP/UA not persisted, logs minute-rounded (`packages/server/src/logger.ts`); ballot header timestamps are NOT rounded (QV-06-REQ-009), so timing correlation of "who voted when" is exposed; TLS terminated outside the server, no Tor test (QV-07-REQ-064).
- No erasure from the append-only log (docs/06:202); no long-term/PQ secrecy (docs/06:199, N-6); no legal validity (docs/06:204, N-9).
- Forbidden words in Phase-1 UI/docs: anonymous, untraceable, unhackable, tamper-proof, coercion-proof (docs/06:206). Enforcement is a non-blocking docs-only lint (`scripts/lint-claims.mjs`), not a UI-catalog lint (QV-02-REQ-082 partial).
