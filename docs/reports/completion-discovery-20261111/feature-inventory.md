## 1. Voting model as specified

Definition of "v1": charter §6.1 says MVP scope is "v0.x -> v1.0" (00-project-charter.md:76); QV-02 §10 maps MVP = v0.9 pilot, v1.0 general (02-product-requirements.md:233). The method set and identity phase are the same for both. The spec status is Draft throughout, so "specified" here means "drafted + provisionally accepted ADRs".

**Headline: v1 mandates exactly four methods: yes/no, single-choice, approval, k-of-n (bounded multi-select), with quorum + simple/supermajority threshold, under a secret-ballot / public-participation (Phase 1) model with revoting. Ranked, weighted and delegation are Phase 2 (deferred; ranked additionally gated and disabled until external review). Score/range, STV, write-ins are not in v1 at all.** Evidence: QV-ADR-006 (decision-log.md:64), QV-20 §2 (20-voting-methods.md:18-25), QV-20-REQ-001 (:72), charter (00-project-charter.md:101), QV-02 (02-product-requirements.md:187,199). Implementation corroboration (not spec): `packages/protocol/src/types.ts:41`, `schema.ts:192`, `manifest.ts:107-121` accept only `yes-no | single-choice | approval | k-of-n`.

## 4. Spec gaps and contradictions noticed

1. **Voter-chosen sequence number survives in QV-07.** QV-07-REQ-024/025 (07-threat-model-security.md:550-551) require signing a "per-voter sequence number" and counting the "highest sequence number", but QV-ADR-016 (decision-log.md:261-266), QV-16-REQ-017 (16-crypto-protocol.md:73) and QV-20-REQ-010 (20-voting-methods.md:81) say there is no voter-chosen seq (log seq + `supersedes` chain). Not conformed in QV-07; I found no errata hit in docs/plan or docs/errata (grep), other errata locations UNVERIFIED.
2. **Roll fixed "in the manifest at signing" vs `roll_commit`.** QV-02-REQ-035 (02-product-requirements.md:126) and QV-04-REQ-009 (04-identity-eligibility.md:247) vs ADR-015 (decision-log.md:254-259: root committed by organizer-signed `roll_commit` bound by `election_open`; manifest root optional). Spec text not yet conformed to ADR.
3. **Spoil reveal published vs private.** QV-20-REQ-011 (20-voting-methods.md:82), QV-02-REQ-044 (02-product-requirements.md:136), QV-05 §3.1 P6 (05-ballot-protocol.md:57) say the plaintext+randomness of a spoiled (Benaloh-challenged) ballot is public/published; ADR-020 (decision-log.md:285-290) says reveal is not published by default.
4. **Manifest field names diverge across specs.** QV-03 uses `quorum_bp`, `threshold.base yes_no|all_cast|eligible`, tie rules `status_quo|drand_lot|runoff|fail|incumbent` (03-governance-and-policy.md:226-243); QV-16 uses `quorum {type,num,den,basis}`, `rule {type:"threshold",...}`, hyphenated tie names (16-crypto-protocol.md:239-242); QV-20 says QV-16 prevails (20-voting-methods.md:55) but QV-03 §7 is unchanged. QV-20 also has `beacon_random` vs QV-03 `drand_lot`. Also QV-16 `bb.witness_quorum` (:250,265) vs QV-18 `witness_policy` list (18-bulletin-board-transparency.md:85).
5. **Ranked cap inconsistent.** QV-20 §8.3 and QV-20-REQ-042: n<=10, weak orders n<=7 (20-voting-methods.md:147,88); ADR-023: n<=12, ties opt-in n<=7 (decision-log.md:303-306). QV-20 §2 also cross-refs STV as "§9.5" whereas STV is §9.4 (20-voting-methods.md:24 vs :203).
6. **Trustee threshold rule: three variants.** QV-02-REQ-032 (02-product-requirements.md:123): t > n/2, t=1 rejected unconditionally; QV-07-REQ-011 (07-threat-model-security.md:533): t<2 allowed only with `single-trustee-degraded`; QV-17-REQ-002 (17-key-ceremony-trustees.md:77): t=1 and t=n allowed with ack flag. Also n<=15 is Must in QV-02 but Should in QV-17-REQ-003 (:78).
7. **Authentication model conflict.** QV-08-REQ-019 (08-architecture-deployment.md:437): signed requests, "no password or cookie sessions"; QV-09-REQ-006 (09-api-data-contracts.md:185): challenge-response producing 12 h bearer tokens stored hashed. Whether a "session" exists is unresolved.
8. **No web admin UI vs organizer UI.** Proposed ADR-P12-1 (decision-log.md:141) "CLI + signed records only", yet QV-10-REQ-004/016/017 (10-user-experience.md:92,104,105) and QV-02 J1 "setup wizard" (02-product-requirements.md:35) assume organizer UI. ADR-P12-1 is still only Proposed.
9. **Verifier page size and priority.** QV-19-REQ-016 (19-client-supply-chain.md:288): Must, < 400 KB; QV-13-REQ-048 (13-accessibility-localization.md:193): Should, < 1 MB. Related: QV-13-REQ-041 voter-flow transfer <= 300 kB (:186) vs QV-30-REQ-030 voting-path bundle <= 120 KB gzip (30-engineering-standards.md:278) (different metrics; unclear).
10. **Backup RPO/RTO differ.** Charter S9: RPO <= 15 min (00-project-charter.md:120); QV-28-REQ-011: RPO <= 5 min for OPEN (28-data-model-storage.md:49).
11. **STH/receipt timing stated differently.** QV-02-REQ-042: inclusion proof within `log.sth_interval` default <= 60 s (02-product-requirements.md:134); QV-05-REQ-004: mmd 30 s (05-ballot-protocol.md:263); QV-18-REQ-011: checkpoint within 1 s (18-bulletin-board-transparency.md:76); QV-07-REQ-041: STH every 60 s, MMD 30 s with "QV-18 prevails" (07-threat-model-security.md:567); ADR-P05-1 says mmd 60 s (decision-log.md:111). Largely reconciled by QV-18 precedence, but QV-02 text is stale.
12. **Proof-of-work priority.** QV-18-REQ-035 PoW "Could, off by default" (18-bulletin-board-transparency.md:102) vs QV-29-REQ-004/005 PoW as part of the Must admission pipeline with difficulty schedule (29-abuse-dos-prevention.md:236-237).
13. **Multi-tenant vs "no multi-tenant SaaS in MVP".** QV-08-REQ-018 (08-architecture-deployment.md:436) mandates tenant isolation (per-tenant DB files); QV-28-REQ-002 (28-data-model-storage.md:40) is per-election files plus a control DB; charter excludes hosted multi-tenant SaaS in MVP (00-project-charter.md:100). Tenancy model is unclear.
14. **REQ id collisions from retained drafts.** `17-portable-membership-credentials.md`, `18-federated-governance.md`, `19-delegation-exit-fork.md` define QV-17-REQ-001..008, QV-18-REQ-001..008, QV-19-REQ-001..010 which duplicate ids in the current QV-17/18/19 (grep counts: 737 distinct ids, but those files each contribute 8-10 ids with the same numbering). SPEC-INDEX.md:74 says not to cite old IDs as active; QV-30-REQ-026 requires REQ ids unique (30-engineering-standards.md:274), so docs-lint would flag this unless the retained files are excluded.
15. **Threshold/base vs method scope.** QV-20 §6 says quorum/threshold apply to "all methods" (20-voting-methods.md:101-105), but QV-16 attaches `rule` only to yes/no contests and the implementation rejects `rule` on other methods (`packages/protocol/src/manifest.ts:125`); outcome for single-choice/approval/k-of-n is top-w by count (03-governance-and-policy.md:232-243). Whether multi-option contests can have a pass threshold is unspecified.
