# Spec errata log

Findings where the specifications (`docs/*.md`), the test vectors (`test-vectors/`) and/or the TypeScript reference
implementation disagree or leave behaviour open. Each entry gives an id, the location, the finding, and the evidence.
Entries are reported, not resolved: the spec owner decides the fix (QV-34 §8.2 step 4: "Any discrepancy is first treated as
a specification ambiguity; QV-16 is amended, then vectors regenerated").

## Second-verifier (Python) findings, 2026-10-21

Source: the independent Python verifier skeleton in `verifier-py/` (`py-qv-verify 0.1.0`), written from QV-16, QV-34 and the
RFCs without reading the TypeScript implementation. "Evidence" cites vector files under `test-vectors/v1/` as they stood on
2026-10-21. None of these entries required changing a vector or the TypeScript code. Where the verifier had to pick a
behaviour, the choice is stated so that reviewers can check it.
