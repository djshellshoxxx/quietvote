# Audit: packages/board and packages/cli (BC-)

- Scope: `packages/board` (tlog, Merkle, checkpoints, witnesses, receipts, equivocation, bundles), `packages/cli` (`qv`, key files, board verify, ballot encrypt/audit)
- Date: 2026-10-21
- **AI-assisted review, not an independent professional audit.** QuietVote is unaudited and not for real elections.
- Method: read all of `src/` in both packages; wrote failing tests first for each material finding; added property, fuzz and mutation tests. Only what was run is claimed below.

## Threat model

**Assets.** (1) Integrity and append-only history of the bulletin board log (entries, checkpoints, receipts). (2) Voter secret seeds, key files, ballot reveal randomness (`xi`) and audit files. (3) The verdict a verifier or voter relies on (VERIFIED / PARTIAL / FAILED, exit codes). (4) The election identity a voter encrypts to (manifest hash, joint key).

**Trust boundaries.** Bundle JSON / board export files (untrusted); checkpoint notes and cosignature lines (untrusted strings); receipts (untrusted); key files, passphrase files, stdin, argv (user-controlled, may be attacker-crafted files); filesystem (permissions, symlinks, pre-existing files); `BoardStore` persistence (may be restored from an old backup or corrupted).

**Adversaries.** Malicious log operator (holds the log key; can fork, roll back, drop or reorder, re-sign a history under their own key shipped in a bundle); malicious or lazy witness; network attacker supplying bundles/election files to voters; co-tenant local user (reads loose-permission files, plants symlinks); corrupted storage.

**Assumptions.** Ed25519 and SHA-256 are sound; `@quietvote/crypto` `ed25519Verify` is strict and total (read: it returns false on bad lengths and non-strict points); at least one honest witness quorum member or an honest pinned checkpoint exists; the verifier obtains the manifest hash / log key out of band.

**Failure modes considered.** Merkle proof malleability and size/index confusion; leaf/node domain separation; checkpoint (signed-note) parsing ambiguity and non-canonical numbers/base64; cosignature replay across texts and key aliasing; equivocation (same size, two roots), rollback (smaller or ahead tree), inconsistent proof; receipt forgery and broken promise; canonical header encoding; fail-open verdicts; path/symlink/permission issues on secrets; secret leakage via argv/stdout/stderr/errors; exit-code integrity (internal error vs verdict).

## Reviewed, no defect found (evidence: code read plus tests that were run)

- RFC 9162 inclusion and consistency verification: domain separation 0x00/0x01; independent naive implementation agreement for sizes 1..200 (existing tests); new fuzz over random trees: flip/drop/truncate/extend/reorder, wrong leaf/root/index, swapped roots, total on negative/NaN/huge/typed-garbage inputs; interior-node-as-leaf second preimage.
- Checkpoint parser: exactly three text lines, canonical decimal size (no leading zeros / `+` / hex / unsafe), canonical padded base64 root of 32 bytes, CRLF rejected, signature name must equal origin; 3000 random mutations never produced a different validly log-signed checkpoint.
- Cosignatures bound to checkpoint text (copy onto another checkpoint rejected), timestamps monotone, future-dated cosigs rejectable online.
- Equivocation (fork / inconsistent / broken promise), rollback (`observeExternalCheckpoint`, constructor guard, `verifyPinAdvance`), pinned checkpoint in `verifyLog`: consistent with existing tests.
- Bundle verification: 400 single-character mutations of headers, bodies, root, size, checkpoints, receipts (each FAILED or rejected, never VERIFIED/PARTIAL); every single-entry drop, plus reorder/duplicate/seq-swap: never verified; missing final checkpoint fails; redactions require a record and give PARTIAL.
- Canonical header encoding rejects trailing bytes and re-encodes to prove canonicality; strict base64/base64url.
- CLI: unknown flags and `--key given twice` rejected, `__proto__`/`constructor` safe (`Object.hasOwn`), secrets never accepted via argv, no seed/passphrase/`xi` in stdout/stderr (tested for success and error paths), audit file 0600 with `O_EXCL`, QVKEY1 mutations (ct/salt/iv/keyId/aad/params/algs/extra fields) all rejected without producing output; random argv never yields exit 70.
