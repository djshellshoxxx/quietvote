# Banned phrases for public claims (read by scripts/lint-claims.mjs)
#
# Sources: docs/07-threat-model-security.md section 12.3 (forbidden or restricted language),
# docs/30-engineering-standards.md QV-30-REQ-034, docs/plan/RISK-REGISTER.md R01.
#
# Format
#   - One rule per line. Blank lines and lines starting with '#' are ignored.
#   - Plain rules are literal and case-insensitive. They match whole words only, so
#     "audited" does not match "unaudited".
#   - 're:' prefix: the rest of the line is a JavaScript regular expression (case-insensitive).
#   - Optional allow-pattern after ' || ': a JavaScript regular expression (case-insensitive).
#     If it matches within 80 characters either side of the hit, the hit is suppressed.
#   - Negation is always checked: if a negation word (not, no, never, nor, without, cannot,
#     can't, isn't, doesn't, don't, un-, non-) appears in the same sentence, shortly before
#     the phrase (within 60 characters), the hit is suppressed. Example: "No system is unhackable".
#   - A line that itself labels wording as a non-claim, unsupported, forbidden or banned
#     (for example 'Non-claim', 'Unsupported', 'Forbidden', 'banned', 'does not promise') is
#     not treated as a public claim, and every rule is suppressed on that line.
#   - Other exemptions (not in this file):
#       * Inline marker <!-- claims-lint-ignore --> on the hit's line or on the line before it.
#         Block form: <!-- claims-lint-ignore-start --> ... <!-- claims-lint-ignore-end -->.
#       * Quoted text, only inside docs/claims/**: text in "double quotes", curly quotes or
#         `backticks` is exempt, because the claims register quotes banned wording in order to
#         classify it.
#
